# NASCON Web Dev — Competition Workspace

This is a prepared workspace, not an application template. It keeps Claude's operating rules and the event-day planning docs ready without choosing a stack, creating a Git repository, installing packages, or creating cloud resources before the live prompt and rules are known.

## Before the timer
1. Open this folder in VS Code and open Claude Code in the sidebar.
2. Read docs/01-LIVE-RULES.md and transcribe the organizer's rules exactly.
3. Save the live prompt in docs/02-PROBLEM-BRIEF.md. Keep the original instructions unchanged in a local reference folder if allowed.
4. Ask Claude to inspect the brief and propose a one-page implementation plan, then start only after the team agrees.
5. Repository: https://github.com/Hafiz-tayyab-23/nascon-web-team-034. Create cloud resources only as the plan/rules require. Do not put credentials in Git.

## Prepared docs
- CLAUDE.md: working agreement and time-box rules.
- docs/01-LIVE-RULES.md: event-specific rules to verify before coding.
- docs/02-PROBLEM-BRIEF.md: live prompt and scope capture.
- docs/03-REQUIREMENTS.md: prioritized acceptance checklist.
- docs/04-DESIGN.md: visual direction and UI quality bar.
- docs/05-ARCHITECTURE-API.md: stack, data, security, service contracts.
- docs/06-TEST-DEMO.md: test, deploy, and presentation checklist.
- PLAN.md: today's 10:00 AM–4:00 PM PKT schedule and decision gates.
- Competition_Rules_and_Guidelines.pdf and problem statement.pdf: official organizer documents (authoritative).

These are intentionally compact. Update them from the live prompt; do not spend the first hour writing more documentation.
