# Test, deployment, and demo runbook

## Before demo
- [ ] Fresh page load succeeds on the deployed URL.
- [ ] Core journey works end to end with the intended account/data.
- [ ] No required action is a dead button.
- [ ] Invalid input is rejected with a useful message.
- [ ] Loading, empty, and error states are understandable.
- [ ] Mobile/narrow layout has no horizontal overflow.
- [ ] Required API endpoints can be shown directly if the prompt asks.
- [ ] No secret or private test account is visible in the browser or repository.
- [ ] README has setup, environment variable names, run commands, and architecture.
- [ ] All required files, URL, branch, and submission are ready.

## Three-minute demo
- 0:00–0:20: Problem, target user, and what is different.
- 0:20–2:10: Demonstrate the core journey with real working interactions.
- 2:10–2:40: Show the strongest differentiator, data/security/architecture evidence, or required API.
- 2:40–3:00: State what is verified, what is a demo assumption, and the next step.

Adapt this timing to the actual judging slot. Keep a backup account and a local/screenshot fallback only if event rules permit.
